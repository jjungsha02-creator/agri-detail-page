## 2단계. 핵심문구 해석 {#2단계}

아래 항목을 모두 작성한다.

- **핵심문구의 의미**: 이 문구가 고객에게 전달하는 메시지
- **고객에게 주는 기대감**: 고객이 이 문구를 보고 기대하는 것
- **해결할 수 있는 구매 불안**: 이 문구가 줄여주는 걱정
- **상세페이지에서 반복해야 할 포인트**: 어떤 단어·개념을 섹션마다 살려야 하는지
- **첫 화면에서의 표현 방식**: 이 핵심문구를 첫 화면에서 어떻게 시각화할지
- **강화된 핵심문구 대안 3~5개**: 기존 핵심문구를 유지하되 더 강한 표현 제안

**예시:**

핵심문구: `비파괴 당도선별 꿀수박`

- 의미: 겉만으로 알기 어려운 당도를 선별 기준으로 해결했다는 신뢰 메시지
- 기대감: "이건 진짜 단 수박이겠구나"
- 해결하는 불안: 맹맹한 수박을 받을까 봐 걱정하는 고객의 불안
- 반복 포인트: 비파괴·당도선별·꿀수박 세 단어를 섹션마다 자연스럽게 반복
- 첫 화면 표현: 상단 배지 형태로 "비파괴 당도선별"을 강조, 메인 문구는 "당도 보고 고른 꿀수박"
- 강화 대안: "당도 확인하고 고른 꿀수박", "맹맹한 수박은 없습니다, 당도선별 꿀수박"

## 3단계. 고객 구매 불안 정리 {#3단계}

농산물 구매자가 실제로 걱정할 만한 내용을 정리한다.
아래를 기본 목록으로 삼되, 과일 특성에 맞게 추가·조정한다.

- 사진과 실물이 다를까 봐 걱정
- 맛이 싱겁거나 맹맹할까 봐 걱정
- 크기가 작을까 봐 걱정
- 배송 중 무르거나 상할까 봐 걱정
- 가격만 싸고 품질이 낮을까 봐 걱정
- 후숙이 필요한지 바로 먹어도 되는지 모를까 봐 걱정
- 중량과 실제 수령량이 다를까 봐 걱정
- 흠집, 반점, 크기 차이가 불량인지 걱정

각 불안 항목마다 → 공감 문구 → 해결 문구 흐름을 미리 구성해 둔다.
사용자가 리뷰 자료를 제공하면 그 내용을 우선 반영한다.

## 4단계. 와디즈 벤치마킹 분석 {#4단계}

SKILL.md의 와디즈 벤치마킹 원칙에 따라 진행한다.

**카테고리 기준:**
- 대상: 헬스·이너뷰티, 전자책, 클래스 (성과가 높은 순으로 우선)
- 제외: 푸드 카테고리 (같은 카테고리 벤치마킹은 차별화가 없음)

**수집 및 선별 순서:**
1. 레퍼런스를 5개 이상 수집한다.
2. 각 레퍼런스의 후킹 유형을 아래 6가지로 분류한다.
3. 서로 다른 후킹 유형과 설득 구조를 가진 3개 이상을 선별해 분석한다.
4. 같은 레퍼런스명·브랜드·페이지 구조는 반복 선택하지 않는다.

**후킹 유형 6가지:**

| 후킹 유형 | 핵심 방식 |
|----------|---------|
| 문제 제기형 | 고객의 고통·불편을 첫 문장에 배치해 공감 유도 |
| 결과 제시형 | 기대 결과·변화를 먼저 보여주고 역방향으로 설득 |
| 권위 강조형 | 수치·인증·전문가·수상 이력으로 신뢰 선점 |
| 비교 설득형 | 기존 제품·방식과의 차이를 대비로 각인 |
| 스토리형 | 메이커·생산자·고객의 이야기로 감정적 연결 |
| 혜택 강조형 | 구매 후 얻는 편익·가치를 구체적으로 먼저 제시 |

선별 시 **최소 3가지 이상의 후킹 유형**이 섞이도록 구성한다.

각 레퍼런스 분석 형식 (후킹 유형 항목 필수):

```
레퍼런스명: [이름]
링크: [URL]
카테고리: [헬스·이너뷰티 / 전자책 / 클래스 중 해당]
펀딩 성과: [달성률 또는 금액]
후킹 유형: [문제 제기형 / 결과 제시형 / 권위 강조형 / 비교 설득형 / 스토리형 / 혜택 강조형]
첫 화면 후킹 문구: [실제 문구]
문제 제기 방식: [어떻게 고객의 고통을 짚었는지]
신뢰/권위 표현 방식: [어떻게 믿음을 줬는지]
구매 욕구를 만든 방식: [어떻게 사고 싶게 만들었는지]
상세페이지 흐름: [후킹 → 문제 → 해결 → 차별점 → ... 순서]
농산물 적용 포인트: [이 농산물에 쓸 수 있는 구조나 방식]
변환 문구: [농산물에 맞게 새로 작성한 문구]
```

**벤치마킹 요약표 (3개 이상 선별 후 반드시 작성):**

| 레퍼런스명 | 카테고리 | 후킹 유형 | 핵심 설득 구조 | 농산물 적용 포인트 |
|-----------|---------|---------|--------------|----------------|
| [이름] | [카테고리] | [후킹 유형] | [구조 요약] | [적용 방식] |

**재조합 원칙:**
최종 기획은 특정 레퍼런스를 그대로 따라 하지 않는다. 각 레퍼런스의 설득 구조를 추출해 해당 농산물에 맞게 새로 작성한다.
예: A의 문제 제기 방식 + B의 신뢰 표현 방식 + C의 구매 전환 흐름 → 새 구조로 합성

접속 불가 시 SKILL.md의 안내 문구를 먼저 출력하고 사용자 링크를 기다린다.

## 5단계. 첫 화면 후킹 문구 {#5단계}

6가지 유형별로 최소 5개 이상 제안한다.
각 문구는 짧고 강하게 — 첫 화면에서 고객이 멈출 수 있어야 한다.
모든 문구는 반드시 핵심문구와 연결된다.

| 후킹 유형 | 방향 | 예시 |
|---------|------|------|
| 문제 제기형 | 고객의 고통·불편을 첫 문장에 배치 | "혹시 맹맹한 수박 받은 적 있으신가요?" |
| 결과 제시형 | 기대 결과·변화를 먼저 제시 | "한 박스 받고 나서, 동네 마트에 못 갑니다" |
| 권위 강조형 | 수치·인증으로 신뢰 선점 | "당도선별 기준 통과율 ○○%, 숫자로 증명합니다" |
| 비교 설득형 | 기존 제품·방식과의 차이를 대비로 각인 | "마트 수박과 한 번만 비교해보세요" |
| 스토리형 | 생산자·고객의 이야기로 감정적 연결 | "20년째 이 밭에서만 키웁니다" |
| 혜택 강조형 | 구매 후 얻는 편익·가치를 먼저 제시 | "제철 딱 2주, 지금 아니면 내년에 먹습니다" |

**기준:** 문구가 예쁘기보다 고객이 "이건 나한테 하는 말이다"라고 느끼게 써야 한다.
유형별로 최소 1개 이상 작성하되, 최종 기획에는 **3가지 이상의 후킹 유형**이 반드시 섞이도록 한다.

## 6단계. 상세페이지 전체 흐름 설계 {#6단계}

10개 섹션으로 구성한다. 모든 섹션은 핵심문구와 연결된다.

```
섹션 01. 첫 화면 후킹      → 고객이 멈추게 만들기, 핵심문구 1개 강조
섹션 02. 공감 / 문제 제기  → 고객이 구매 전 걱정하는 부분 짚기
섹션 03. 해결 제안         → 이 상품을 선택해야 하는 이유 연결
섹션 04. 상품 핵심 차별점  → 산지·품종·수확 시기·선별 방식·맛·식감
섹션 05. 맛 표현 구간      → 단맛·과즙·식감·향을 감각적으로 표현
섹션 06. 실물 이미지 구간  → 전체·단면·박스·먹는 컷 배치
섹션 07. 비교 / 기준 제시  → 일반 상품과의 차이, 좋은 상품 고르는 기준
섹션 08. 구매 전 확인사항  → 크기·중량·배송·보관법·후숙법
섹션 09. 주의사항 / 교환반품 → 농산물 특성상 필요한 고지
섹션 10. 마지막 구매 유도  → 지금 사야 하는 이유, 제철·한정·산지 직송
```

## 7단계. 섹션별 상세 기획안 {#7단계}

각 섹션을 아래 카드형 Markdown 형식으로 작성한다.
코드 블록이나 표 형식이 아니라, 제작자가 바로 읽고 쓸 수 있는 구조다.

**작성 형식:**

---
## 섹션 01. 첫 화면 후킹

**역할**
[고객이 첫 화면에서 멈추게 만들기]

**제목 문구**
[짧고 강한 메인 문구]

**보조 문구**
[제목을 뒷받침하는 1~2줄]

**본문 문구**
[2~4줄 설명]

**핵심문구와의 연결**
[이 섹션이 핵심문구와 어떻게 이어지는지]

**강조해야 할 단어**
[굵게 처리할 단어들]

**필요 이미지**
[이미지 설명]

**디자인 방향**
[배치·색상·폰트 처리 방향]

**주의할 점**
[이 섹션에서 피해야 할 표현 또는 실수]

---

**7단계에서 반드시 지킬 것:**
- 모든 섹션에 **핵심문구와의 연결** 항목을 빠짐없이 작성한다. 이것이 없으면 섹션이 핵심문구와 분리된다.
- 섹션 흐름 전체가 공감 → 해결 → 확신 → 구매로 이어지는지 확인한다.
- 출력 문구에 이탤릭체(`*텍스트*`)를 사용하지 않는다. 강조는 볼드(`**텍스트**`)만 사용한다.

## 8단계. 이미지 컷 리스트 {#8단계}

각 이미지 컷마다 아래 형식으로 작성한다.

```
컷 번호: 01
컷 이름: 대표 이미지 (히어로 컷)
이미지 역할: 첫 화면에서 고객이 멈추게 만드는 가장 강한 이미지
어떤 장면: [구체적인 장면 묘사]
함께 들어갈 문구: [이 이미지에 올릴 텍스트]
피해야 할 느낌: [어두운 조명, 배경 잡음, 인공적인 색감 등]
촬영/제작 방향: [앵글·조명·배경·소품 방향]
```

필요한 이미지 컷 유형 (과일 특성에 맞게 선택):
- 첫 화면 대표 이미지 (히어로 컷)
- 과일 전체 컷 (크기·모양 확인용)
- 과일 단면 컷 (당도·과즙 확인용)
- 손에 든 크기 비교 컷
- 박스 포장 컷 (배송 신뢰용)
- 과즙·식감 강조 컷 (먹고 싶게 만드는 컷)
- 식탁 위 연출 컷
- 가족·아이가 먹는 느낌 컷 (타깃이 맞을 때만)
- 산지 느낌 컷 (신선·신뢰용)
- 선별 과정 컷 (선별 방식 강조할 때)
- 보관·후숙 안내 컷

핵심문구와 관계없는 장식용 이미지는 제안하지 않는다.

## 9단계. 디자인 방향 {#9단계}

추상적으로 쓰지 말고, 제작자가 바로 참고할 수 있게 구체적으로 작성한다.

아래 항목을 모두 포함한다:

| 항목 | 내용 예시 |
|------|----------|
| 전체 톤 | 신선하고 깨끗한 자연 느낌 |
| 배경색 | #FFFFFF (흰색) 또는 #F9F6F0 (아이보리) |
| 제목 컬러 | #1A1A1A (진한 검정) |
| 본문 컬러 | #444444 (중간 회색) |
| 강조 컬러 | 과일의 주요 색상에서 추출 (예: 수박 → #E84545) |
| 폰트 강약 | 제목 Bold, 본문 Regular, 강조단어 Semi-Bold |
| 여백 방향 | 섹션 간 넉넉하게, 텍스트 밀도는 낮게 유지 |
| 이미지 톤 | 자연광 기반, 채도 약간 높게, 과도한 보정 피하기 |
| 카드형 박스 | 구매 전 안내·비교표 섹션에 활용 |
| 정렬 방향 | 히어로 섹션 중앙정렬, 본문 섹션 좌정렬 추천 |
| 주의할 요소 | 강조 색이 너무 많으면 산만해짐 / 배경이 탁하면 과일 색감이 죽음 |

## 10단계. 구매 전 안내 문구 {#10단계}

딱딱한 고지문이 아닌, 고객이 이해하기 쉬운 말투로 작성한다.

필요에 따라 아래 항목을 포함한다:

- **중량 안내**: "표기 중량은 포장재 포함 기준입니다" 등
- **크기 안내**: "개체별로 크기 차이가 있을 수 있습니다"
- **혼합과 안내**: 혼합과 상품인 경우 외관 차이 명확히 안내
- **산지 사정 안내**: 기상 여건에 따라 수확·발송 일정이 변동될 수 있음
- **배송 안내**: 산지 발송 기준, 배송 소요일
- **보관법**: 수령 후 바로 냉장 보관 또는 상온 보관 방법
- **후숙 방법**: 필요한 경우 후숙 방법과 기간
- **자연물 특성 안내**: "자연에서 자란 농산물이므로 크기·색상에 개체 차이가 있습니다"
- **흠집·반점 안내**: 가정용·혼합과·못난이·주스용의 경우 외관 흠집, 스크래치, 멍, 반점이 있을 수 있음을 명확하게 안내
- **교환·반품 안내**: 농산물 특성상 단순 변심 교환·반품이 어려울 수 있음, 불량 기준 안내

각 항목에 ✅ (통과) 또는 ⚠️ (수정 필요) + 이유를 표시한다.

## HTML 선택 출력 {#html선택출력}

HTML 미리보기는 기본 출력에 포함하지 않는다.
사용자가 아래 중 하나를 요청할 때만 출력한다:
- "HTML로도 만들어줘"
- "미리보기 HTML 줘"
- "코드 형태로 줘"
- "HTML 버전 봐야 해"

HTML 출력 시 반드시 먼저 이 안내 문구를 출력한다:
> "아래는 구조 확인용 HTML입니다. 실제 디자인 완성본이 아니라 상세페이지 흐름을 확인하기 위한 코드입니다."

**HTML 작성 규칙:**
- 각 섹션은 `<section>` 태그로 구분
- 제목은 `<h1>`, `<h2>`, `<h3>` 태그 사용
- 보조 문구와 본문은 `<p>` 태그 사용
- 이미지 자리는 `[이미지: 필요한 컷 설명]` 형태로 표시
- 핵심문구는 첫 화면과 주요 섹션에 반복 표시
- CSS는 최소한으로, 구조 확인이 쉬운 정도로만 작성
- 과도한 스타일링은 넣지 않음
